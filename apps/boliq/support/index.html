Hilfe

Beim ersten Start kommt zuerst eine kurze Erklärung der App, danach Apples Altersfreigabe für Kontakte. Die Einführung wird nach deiner Bestätigung lokal als gesehen gespeichert. Vor dem Öffnen einer Runde wählt der Host „Gezielt“ oder „Zufällig“. Der Zufallsmodus berücksichtigt nur verbundene Mitspielende; bei einer neuen Nähe-Anfrage entscheidet die ausgeloste sichtbare Person weiterhin selbst.

Klassisch: Geräte auf den Tisch legen. Solo ist ohne Netzwerk möglich. Für das Zweier-Display-Spiel dasselbe WLAN verwenden, Spiel öffnen, Einladung teilen/importieren, beide Zustimmungen und Displayrollen bestätigen. Der Host startet. Wischen oder Richtungsbutton spielt; nach Ankunft des Balls irgendwo auf das Spielfeld tippen. Spontan: Beide öffnen BOLIQ. Wer Empfang freigibt, ist auch auf der Startseite sichtbar; ein Objekt auszuwählen oder selbst zu senden ist dafür nicht erforderlich. Tippe auf einen sichtbaren Namen. Die andere Person muss die Anfrage annehmen, bevor der erste Pass beginnt; der Host kann während der Runde weitere sichtbare Personen bis insgesamt acht hinzufügen. Die Nähe-Suche funktioniert nur lokal bei geöffneter App; es gibt keine Internet-Online-Liste. Für Handheld-Gruppen mit 2–8 Personen öffnet der Host eine Runde mit einem sechsstelligen Code. Andere geben diesen Code ein und fragen den Beitritt lokal an; der Host bestätigt jede Person. Der Code ist öffentliches Suchmerkmal, kein Passwort. Sitzungsschlüssel werden erst nach Annahme in der verschlüsselten Verbindung übertragen. Die bisherige Dateieinladung bleibt eine Alternative. Play, Party und Meet bieten verschiedene Situationen mit unterschiedlichen Fangzeiten; Nur Party bietet den zusätzlichen Spielmodus „The Bomb“: feste Zeit von 10–120 Sekunden oder zufällige 20–60 Sekunden. Bei Ablauf verliert, wer zuletzt gefangen hat; während eines Wurfs bleibt das die werfende Person bis zum bestätigten Fang. Die Verbindung nutzt Bluetooth oder WLAN nach Wahl des Systems. Bei Verbindungsverlust eine neue Runde öffnen.

Help

First launch briefly explains the app before Apple age sharing for contacts. Acknowledging the introduction stores a local seen flag. Before opening a round, the host chooses Targeted or Random passing. Random passes only select connected members; a new nearby request still requires the selected visible person to accept.

Classic mode: keep devices on the table. Solo uses a practice wall. For the two-screen game, use the same Wi-Fi network, host, share/import the invitation, approve pairing and confirm positions. The host starts. Swipe or use the pass button; tap anywhere on the court once the ball arrives. Spontaneous play: both people open BOLIQ. Someone who enables reception can receive on Home without choosing an object or sending first. Tap a visible name; the other person must accept the request before the first pass starts; the host can add more visible people during the round, up to eight in total. Discovery is local and works only while the app is open; there is no Internet-wide online list. For private handheld groups of two to eight, the host opens a round with a code; others enter it nearby, and the host approves joining. File invitations remain an alternative. Play, Party and Meet offer situations with different catch windows; Only Party offers The Bomb as an additional game mode: a fixed 10–120 seconds or a random 20–60 seconds. The last confirmed catcher loses when time runs out; during a throw, ownership stays with the sender until the next catch. The system chooses Bluetooth or Wi-Fi. Open a new round after a lost connection.

Reception and nearby rounds (22 October 2026)

Optional reception and cue preferences are saved only on this device. Once enabled, reception can resume on the home screen after a fresh suitable Apple age permission, without choosing an outgoing object. Disable it on Home or in Settings. Reception ends when backgrounded or locked; returning home from a round can resume the chosen reception preference. Incoming requests display their virtual object before acceptance. Sound, haptics and banners are foreground-only cues, not push notifications. For a group, the host opens a round with a six-digit code. Others enter it and request to join nearby; the host approves each person. The publicly advertised code is a search label, not a password. Invitation secrets are transferred only after approval over the encrypted device session. File invitations remain an alternative.
